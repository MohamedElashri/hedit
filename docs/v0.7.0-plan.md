# hedit v0.7.0 development plan

Develop the five tracks in parallel from the published `v0.6.2` commit
`7f653b7`. Bring reviewed changes together on `release/0.7.0` to measure
the combined build and test the release candidate.

## Worktrees

The release worktrees live under `.worktrees/v0.7.0/` inside the main `hedit`
checkout. Each track has its own branch and build directory.

| Directory | Branch | First change |
| --- | --- | --- |
| `idle-performance/` | `v0.7.0/idle-performance` | Capture an idle CPU and memory baseline and identify the largest sources of wakeups and retained memory. |
| `ssh-performance/` | `v0.7.0/ssh-performance` | Measure SSH setup phases, idle RPC traffic, and time to resume editing after a disconnect. |
| `ssh-ux/` | `v0.7.0/ssh-ux` | Open a keyboard-first host and recent-workspace picker directly from the Command Palette. |
| `ssh-imports/` | `v0.7.0/ssh-imports` | Import selected SSH aliases and sync them as the configuration changes. |
| `plugin-api/` | `v0.7.0/plugin-api` | Load a versioned user extension manifest and expose one snippet command in the Command Palette. |
| `stability/` | `v0.7.0/stability` | Reproduce and fix the highest-impact save, recovery, or shutdown defect with a focused regression test. |
| `integration/` | `release/0.7.0` | Collect reviewed changes, compare the integrated build with v0.6.2, and prepare the release candidate. |

## Idle CPU and memory

- Measure release builds under the same OS, display backend, profile, fixture,
  and observation window. Record CPU time per minute, wakeups or frames per
  minute, and resident memory after warm-up. Sample an empty window, a large
  local workspace, and a previously busy workspace after closing tabs or
  panels. Measure focused and unfocused windows separately and record enabled
  features and active workers.
- Trace wake sources around `HeditApp::next_wake` and the frame loop in
  [src/app.rs](../src/app.rs). Reduce unnecessary repaint requests and periodic
  work. Inspect retained layout, search, Git, and worker state after closing a
  view or project, then bound or release the allocations that dominate memory.
- Use `HEDIT_NATIVE_TRACE_FILE` to attribute native frame work in a separate run
  and the `profile_workspace_interaction` test for large-tab and large-document
  comparisons. Check that caret blink, external changes, worker completions,
  and typing still update promptly. Use the v0.6.2 measurements to set CPU
  and memory targets for each scenario before comparing the optimized build.
  [Native frame diagnostics](../DEVELOPER_GUIDE.md#native-frame-diagnostics)

## SSH performance and reliability

- Extend the [workspace probe](../tests/support/remote_workspace_probe.rs)
  and [live harness](../scripts/test-remote-live.py). Measure cold installation
  and warm connection separately through the first usable document. Count SSH
  launches and idle change checks, measure durable edit latency, and time
  reconnect through to an editable document. Run on loopback and under a fixed
  added latency. Report sample counts and median and tail latencies.
- Profile the account probe, helper setup, and RPC handshake before changing
  bootstrap. Evaluate the idle `Changes` polling interval separately against
  external-change freshness and disconnect detection. Keep host verification,
  recovery directories, writer fencing, and durable receipt validation intact.
- Exercise dropped connections before and after commit, worker restarts,
  conflicting external changes, cancellation, and repeated reconnects.
  Verify that acknowledged edits appear exactly once, pending edits survive a
  transport interruption, uncertain saves require reconciliation, and reconnect
  clears execution trust. Run `make test-remote` and `make test-remote-live`.
  [Live SSH fixture setup](../DEVELOPER_GUIDE.md#ssh-architecture-and-testing)

## SSH connection workflow

- Make the existing palette command open a picker with configured aliases,
  direct host entry, and recent remote folders. Give **Connect to Host** and
  **Reopen Workspace** distinct actions so users can predict which folder opens.
  Use the same launches from Remote Explorer and support keyboard selection,
  confirmation, and cancellation. Use the VS Code connection and reopen flows
  as a reference. [Connect to a remote host](https://code.visualstudio.com/docs/remote/ssh#connect-to-a-remote-host)
  [Reopen a remote folder](https://code.visualstudio.com/docs/remote/ssh#remember-hosts-and-advanced-settings)
- Show the host and workspace identity during setup and when connected. Add
  actionable status and retry options for setup failure and disconnection.
  Follow with keyboard browsing inside the authorized remote root. Opening a
  different root uses its own managed workspace and host recovery state.
- Exercise first connection with and without a configured alias, reopening a
  saved folder, cancellation, failure recovery, and disconnect with pending
  edits. Use existing headless UI tests and a live loopback workflow.
  [Current SSH workflow](../USER_GUIDE.md#ssh-remote-workspaces)

## Lua extension API

- Keep v0.7.0 on hold until the plugin implementation, security regressions,
  packaged smoke checks, and extension guide are verified together.
- Keep v1 JSON snippets and file templates compatible. V2 adds bundled Lua 5.4
  source and explicit selection read and replace permissions. Bind approval to
  one command, its capabilities, and the exact installed manifest. Use explicit
  review for installation, updates, and uninstall. Changes invalidate approvals
  and outstanding proposals.
- Launch a separate OS-confined worker per command with a text-only Lua loader,
  a restricted standard library, bounded IPC, and execution limits. Start
  executable support on Linux x86-64 and ARM64. Keep other builds fail-closed and retain
  declarative extensions across platforms. Run native sandbox tests on every
  platform that enables executable plugins before extending that support.
- Run the manifest, approval, worker, sandbox, and editor regressions. Verify
  cancellation, stale install and uninstall reviews, racing revocation, input
  and resource limits, Unicode and CRLF, and one-step undo. Install and run the
  included example with the packaged application. Cover run-once consent, signed
  updates, edit previews, and save-hook fallback. [Extension guide](extensions.md)

## Crash and edge-case fixes

- Triage reproducible defects by severity. Start with data loss and crash risks
  in saves, checkpoints, and quit. Then cover stale worker replies after a tab,
  pane, or workspace closes, along with extremes in size and position handling.
- Keep a reproduction and a regression test with each fix. Check that failed or
  interrupted operations preserve recoverable text and that retrying reaches a
  consistent state. Start with [recovery](../tests/recovery.rs),
  [save security](../tests/save_security.rs), and
  [close and quit](../src/app/close_tests.rs).

## Linux idle measurements

Compared the published Linux x86-64 v0.6.2 binary with optimized integration
commit `f66574e` on the same machine using a private Xvfb display and Mesa
software rendering. Each scenario used a fresh configuration and session,
disabled caret blink, and sampled the editor process for 12 seconds after a
7-second warm-up. CPU is Linux user plus system CPU time, with 100% equal to
one core. RSS is the median of one-second process samples.

| Idle scenario | CPU v0.6.2 | CPU integration | RSS v0.6.2 | RSS integration |
| --- | ---: | ---: | ---: | ---: |
| Named file over loopback SSH | 670.28% | <0.1% | 166.38 MiB | 169.20 MiB |
| Empty editor | 0.08% | 0.08% | 149.50 MiB | 151.71 MiB |
| Local folder with 13 files open | 0.17% | 0.08% | 191.07 MiB | 193.92 MiB |
| After closing four local tabs | 0.08% | 0.08% | 189.60 MiB | 190.40 MiB |
| After closing eight 15,000-line local tabs | 0.08% | 0.08% | 244.66 MiB | 247.85 MiB |

The remote result isolates the repaint loop in the Git marker scheduler.
In a separate test, the same 23,000-line file was open in four editor groups,
then the layout returned to one group. Median RSS after the collapse was
396.26 MiB in v0.6.2 and 353.88 MiB in optimized commit `56cc35f`, a reduction
of about 11%. RSS stayed similar or slightly higher in the other workloads.

Closing tabs and editor groups now drops their derived caches, as verified by
the cache lifecycle regression test. The split-window benchmark also exposed
an extra idle wake from the local Git marker timer. Fresh markers now wait for
input or an existing watcher frame before rechecking the baseline.

On optimized commit `5953846`, the confirmation run measured 0.08% of one
core for both the SSH and collapsed-grid workloads. The collapsed-grid median
was 344.69 MiB, 51.57 MiB below the published build in this fixture.

### Shared Lua runtime and macOS sandbox adapter

The runtime now has one Lua 5.4 engine for source loading, allowed libraries,
settings, batch protocol, replacement validation, and instruction/memory limits.
The Unix supervisor shares delivery, approval-lock lifetime, cancellation,
deadlines, and child reaping. Linux's existing seccomp policy is an OS adapter;
macOS adds a signed App Sandbox helper with exactly one entitlement and hardened
runtime. The helper reuses the editor executable. Packaging signs the nested
universal helper before the outer app. Development Make targets prepare it too.

Before sending selection bytes, the parent validates the running helper's
signature, identifier, exact entitlement dictionary, and signing team. Native
macOS tests verify private fixture read/write denial, loopback connection denial,
closure of an intentionally inherited descriptor, writable/executable memory
denial, CPU limits, rejection of an overprivileged signed helper, and detection
of a 300 MiB native allocation by the 256 MiB process-footprint monitor. This is
additional to Lua's shared 16 MiB allocation and instruction limits. macOS uses
physical footprint rather than Linux's address-space cap because shared-cache
virtual mappings exceed that cap. App Sandbox still permits its own container
and system resources; its native policy is different from Linux's syscall
allowlist.

The runtime integration suite now executes on macOS: Unicode across pipe reads,
strict results and invalid requests, instruction and allocation limits, the
shipped Markdown example, and 16-selection typed batches. The signed bundle
CLI test also runs actual Lua fixtures. macOS CI now checks the packaged helper's
architecture slices and executes a Lua fixture from the distributed app.

With explicit approval for the disposable test configuration, the native editor
passed command approval, preview/apply, Undo restoring text and selection, and
the separate Markdown on-save binding. Cmd+S invoked the real confined worker
inside its 400 ms budget and saved the expected UTF-8/CRLF bytes. One Undo restored
the pre-hook dirty text. The isolated test process was stopped afterward.

### Windows Lua adapter and hosted validation

Implemented the Windows process adapter, initially behind an opt-in validation feature.
Each invocation creates a capability-free AppContainer, copies the shared
executable into a private image directory with a protected owner/container DACL,
and passes only standard pipe/NUL handles through an explicit inheritance list.
Creation attributes attach the worker job and enforce dynamic-code and child
creation restrictions before execution. The parent checks the suspended token,
container SID, capabilities, job membership, and limits before resuming it. The
worker checks its token, mitigations, job, and pipe handles before consuming its
request. The job limits native memory to 256 MiB, CPU to two seconds, and active
processes to one; parent cancellation/deadline paths terminate and wait for it.
The profile and copied image are cleaned after the invocation.

A dedicated CI workflow tests x86-64 Windows and Windows 11 ARM. Native probes
cover private file read/write, loopback network access, exclusion of an
intentionally inheritable sensitive handle, executable-memory denial, native
allocation limits, process creation denial, CPU termination, job-owner cleanup,
and cancellation/deadline handling. Feature-enabled shared-engine tests cover
16 selections, Unicode/settings, a real on-save worker budget, Lua limits, and
signed distribution fixtures. Launch timings are uploaded as diagnostic
artifacts. Native Windows results are recorded below; a Mac cross-target type
check alone does not validate these security properties.


Windows CI found two launch problems before any Lua ran. An empty environment
prevented AppContainer creation; the adapter now supplies only OS-derived
`LOCALAPPDATA` and `SystemRoot`, with native assertions that editor PATH and test
control variables are absent. After that fix the copied GUI-linked executable
exited with `0xc0000142` before Rust initialization. The engine and OS adapters
have therefore moved into the GUI-independent `hedit-plugin` crate, with a small
headless Windows worker executable. The editor keeps a forwarding module and
uses the same scalar types and runtime. Windows packaging now includes the
worker. Native CI tests the core before compiling editor integration; no second
Lua implementation or GUI permission grant is introduced. Native results for
this layout are pending.

The full macOS suite after extraction passed 1,264 Rust/renderer tests and 41
Python checks. Windows still reproduced the pre-main DLL failure in a service
session. Parent-only profile APIs now load from System32 on demand, and the
worker no longer links the shell known-folder helper. Its environment retains
only the Windows profile path and OS directory. A PE import-table CI check
rejects GUI/profile DLL startup dependencies before native execution tests.
